# Red Queen Findings - Quick Reference

## 🔴 CRITICAL: Do Not Deploy Until Fixed

### 1. Symlink Attack (CWE-59)
**File:** `src/intent/interview_storage.gleam`
**Issue:** CLI follows symlinks, allows arbitrary file read

```bash
# Exploit:
ln -s /etc/passwd .intent/sessions.jsonl
gleam run -m intent sessions  # Reads /etc/passwd

# Fix:
pub fn safe_read(path: String) -> Result(String, String) {
  use is_symlink <- result.try(simplifile.is_symlink(path))
  case is_symlink {
    True -> Error("Security: Refusing to follow symlink")
    False -> simplifile.read(path)
  }
}
```

**Beads:** `intent-cli-83rb`, `intent-cli-x22j`, `intent-cli-k5qu`

### 2. Silent Data Loss (CWE-755)
**File:** `src/intent/interview_storage.gleam:513-558`
**Issue:** Truncated JSONL returns empty list, hides corruption

```bash
# Reproduce:
head -c 500 .intent/sessions.jsonl > temp
mv temp .intent/sessions.jsonl
gleam run -m intent sessions
# Output: {"success":true, "total":0}  # 381 sessions hidden!

# Fix:
# Change line 528-529 from:
|> result.map_error(fn(_) { Nil })  # Silently skip
# To:
|> result.map_error(fn(e) { LogError(e); Nil })  # Log errors
# And at end: if errors > 0, return Error(...) not Ok([])
```

**Beads:** `intent-cli-4c5t`

---

### 3. Export with Corrupted Data (CWE-703)
**File:** Export command (session export logic)
**Issue:** Export succeeds, generates template spec with corrupted input

```bash
# Reproduce:
# Corrupt session answers in .intent/sessions.jsonl
gleam run -m intent export <session-id>
# Output: {"success":true}  # But spec is template!

# Fix:
# Add validation before export:
fn validate_for_export(session: Session) -> Result(Nil, String) {
  case list.length(session.answers) {
    0 -> Error("Cannot export: No answers captured")
    _ -> Ok(Nil)
  }
}
```

**Beads:** `intent-cli-pn1w`
